## Reader boundary

The [stable-input design](plans/dtd-stable-reader.md) adds a private UTF-8
`DtdReader<'input>`. It returns ordinary XML events and moved DTD events without
borrowing controller storage or requiring acknowledgement. Physical values
borrow the immutable constructor input; generated, replacement and defaulted
values own their storage. Returned events can survive later reads and reader
drop, while Rust prevents them from escaping the source lifetime or coexisting
with mutable access to the input.

One parser state and ownership budget cross the ordinary, declaration and body
phases. The handoffs also preserve the DTD catalog, entity frames, reference
counters, occurrence nonce and standalone value. The reader reserves its phase
slot before moving ordinary state. DTD End is returned before fallible body
construction. Panics while moving phases or releasing a token leave both the
reader and the direct content controller poisoned with truthful progress.

Before DTD entry, cursor behavior is byte-for-byte the public Reader behavior.
After entry, `position()` is the accepted primary-source high-water mark;
generated bytes never advance it. The last delivered origin changes only after
a successful publication and survives EOF and sticky errors. `into_inner`
returns the original byte slice, including a UTF-8 BOM.

## Stable borrowing and normalization

Physical source mapping uses checked absolute ranges and preserves the exact
occurrence when equal tokens repeat. DTD units move by value. No unsafe code,
self-reference or forged lifetime is used.

Explicit physical attributes share the catalog's existing normalization pass.
The pass compares emitted UTF-8 bytes with the raw input while it performs the
normal grammar, XML-character, declaration-type, reference and quota checks. A
complete byte match returns `Cow::Borrowed` with no owned-byte request. The
first mismatch, or final truncation for tokenized whitespace, materializes the
matched prefix once and continues through the existing owned append path.
Defaults, generated values and all earlier catalog/Writer/Stream callers keep
their owned policy, capacity requests and error order.

The stable-only comparison and prefix copy are charged to bounded catalog work.
Native value and expanded-byte limits still apply when no String is allocated.
Tests pin first/middle/last transformations, Unicode, EOL conversion,
references, unavailable dependencies, exact/one-short work and capacity
ceilings, and the actual capacity retained by a shortened long input.

## Verification

The final tree passes 670 library tests in debug and release and 13 doctests.
The identical production tree passed the full debug and release all-target
matrix: 1,106 tests passed, none failed and nine documented external-oracle
tests were ignored. Strict all-target Clippy, formatting and diff checks pass.

Three positive lifetime controls retain physical and generated results across
reads, scope unwind and drop. Independent negative probes reject an event that
outlives its input (E0597), input mutation while an event is live (E0502), and a
name view that outlives its owning value (E0597).

The mutation campaign exercised 45 distinct faults. Forty-one were killed by
runtime assertions and four invalid lifetime constructions were rejected by the
compiler. The final holistic review found no Critical, Important or Minor
findings. It explicitly covers exact repeated-token mapping, parser/catalog/frame
continuity, standalone propagation, held-End ordering, reservation atomicity,
inner and outer unwind poison, lazy-output work/capacity accounting, UTF-8 byte
matching, ownership, sticky errors and public Reader parity.

Observed aarch64 rustc 1.95.0 size/alignment in bytes: public Reader 392/8,
private DtdReader 944/8, Phase 2240/8, ContentControllerCore 2240/8,
DtdBodyState 712/8, Event and ReaderEvent 88/8, and DtdUnit 56/8. These are
measurements, not stable layout promises. No comparative performance claim is
made for this checkpoint.

## Remaining work

scanner, declaration, catalog, frame, text and replacement quota through the
facade with exact typed location/stickiness tests. Add the surface to the
coverage-guided fuzz campaign and meet the repository's 100% fuzz-coverage
criterion. Measure DOM and streaming behavior against the public paths and
pinned libxml2. Decide whether a stable UTF-16 API owns decoded storage or uses
a separate lending interface. Review public event/error names, FFI ownership
and allocator-aware Rust 1.100 construction before exposing the surface to
language bindings.
