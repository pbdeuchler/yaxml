## Scope and accounting contracts

There are **32 scalar SessionLimits settings**, plus six `Limits` and two
`DecodeLimits` settings on Reader constructors: 40 fields in total.
`SessionLimits` itself has only `declarations`, `text`, and `local`
([definition](../../src/stream/dtd.rs)). Its nested fields have different scopes:

- Constructor preflight checks the whole original input. InputBytes includes
  the UTF-8 BOM; DecodedBytes excludes it. UTF-16 remains rejected exactly as
  public Reader rejects it. Session configuration is not eagerly validated.
- Ordinary parsing uses the existing Reader and ParserState. Session-only
  ceilings are inactive until a DOCTYPE; a DTD-free document must still parse
  when those settings are zero or a body scratch sum would overflow.
- DTD scanning counts header, units, separators, PE spellings and real closing
  delimiters. Scanner work is cumulative across physical and restarted PE
  scanners; unit/scratch byte limits reset at each released unit.
- `declarations.max_physical_bytes` counts physical bytes from the DOCTYPE start
  through body/epilog, including physical PE/GE reference spelling. It excludes
  prior prolog/BOM bytes and generated bytes. Whole-input preflight separately
  includes the entire input.
- `declarations.max_owned_bytes` bounds DTD raw-unit promotion only. Stable
  physical units borrow and spend zero of it; PE-generated raw units spend their
  complete raw length. It is not a body-event ownership ceiling. Parser
  `Limits.max_owned_bytes` independently covers the same promoted output plus
  normalized/default/generated output and retained parser strings.
- Catalog storage, per-value length, cumulative emitted expanded bytes and
  reference work are separate from those two ownership ledgers. Catalog
  ExpandedBytes counts pre-collapse emitted bytes, not final normalized length.
- Frame attempts/depth/work/expanded bytes are separate from catalog value
  frames. A physical reference costs a frame attempt but no spelling bytes in
  Frame ExpandedBytes; a nested reference consumes its spelling in its parent
  frame. Consumed replacement bytes also spend Frame ExpandedBytes. Empty and
  failed lookups cannot bypass attempts/work. A quota-rejected attempt need not
  increment a counter; earlier permitted lookup/depth work may already be charged.
- The shared DTD/body work ceiling begins at
  `declarations.max_work`; body construction adopts
  `min(declarations.max_work, text.max_work)` with all spent work retained.
  This is a declared scanner/reference/grammar/copy/catalog/frame work model,
  not a count of CPU instructions or all ordinary pre-DTD parser work.
  ParserState Budget is the event/owned-output accounting owner, not a second
  global work ledger.

The implementation is at `DtdReader::{read_next,start_dtd,start_content}`
([reader/dtd.rs](../../src/reader/dtd.rs)),
`DtdController::{drive,drive_replacement,process_ready,enter_parameter,
commit_source,into_body_state}` ([controller](../../src/dtd_controller.rs)),
and `ContentControllerCore::{with_source,drive,prepare_publication,take_event}`
plus its `account_publication` helper
([content](../../src/dtd_controller/content.rs)).

## Smallest complete test implementation

Add one private child module, `tests/internal/dtd_reader_quotas.rs`, wired under
`reader::dtd` only. Use **eight table-driven groups**, Q1–Q8 below, with one
shared bounded drain/assertion helper and a small test-only configuration value.
No generic resource framework or copy of the parser's implementation is needed.
Most scalar rows have one-short/exact/one-above controls; existing complete
Reader controls remain the acceptance evidence for rows already marked E.

1. **Q1 — constructor and ordinary/DTD entry complements.** Reuse complete
   UTF-8 input and existing three constructors. Prove invalid Session settings
   do not affect `<r/>`; preflight InputBytes still wins before bad body scratch
   configuration. With BOM + the 16-byte tiny document, whole-input boundary is
   19 while decoded boundary is 16. Add a ten-byte physical body tag under a
   nine-byte raw or decoded ceiling, isolating the winning limit; nine still
   admits the DOCTYPE prefix. Keep existing UTF-16 rejection and ordinary cursor
   tests unchanged.

2. **Q2 — scanner and unit matrix.** Use `<!DOCTYPE r><r/>` for header limits
   and `<!DOCTYPE r [UNIT]><r/>` for model/attribute definitions.
   Header raw length is 12 and root metadata token count is 1.
   `<!ELEMENT r (a)>` needs depth 1 (opening '(' is unit byte 12);
   `<!ATTLIST r a CDATA #IMPLIED>` needs one definition (name a at unit byte 12).
   Test the distinct accepted positions of scanner-vs-grammar rejection.
   Add native cumulative scanner work through repeated PE expansion:
   `<!DOCTYPE r [<!ENTITY % p '<!--x-->'>%p;%p;]><r/>` has 45 physical DTD
   bytes plus two 8-byte replacements: scanner boundary **61**.
   A separate ceiling 58 stops in the second replacement at local byte 7,
   with physical reference 40..43 and physical high-water 43.
   Use a PE-created ELEMENT model with model-depth zero for a generated
   semantic-unit error. Do not demand an impossible PE-only byte-limit case:
   allowing its longer physical ENTITY literal can already imply enough
   shared per-unit byte allowance for the shorter replacement unit.

3. **Q3 — catalog matrix.** Use Header + ENTITY e='x' for declaration/binding/
   storage boundaries 2/1/2. Use `<!DOCTYPE r><r a='v'/>` for body value/
   expanded limits 1, and native catalog work **14** (12 for Header + 1 input
   value byte + 1 stable comparison byte). Use explicit `&amp;` for reference
   count 1, and e='x' with attribute `&e;` for inclusion depth 1.
   Include one read default, one PE-created binding, one cumulative expansion
   failure after a prior declaration, and an indirectly included replacement
   error. Assert declaration ordinal/raw-unit-relative ValueLocation and
   replacement-local ValueLocation distinctly from the physical anchor.
   Existing direct lazy-Cow tests remain component oracles, not substitutes for
   these real Reader calls.

4. **Q4 — frame matrix and continuity.** One physical GE e='x' needs depth 1,
   attempt count 1, native frame work 2 (entry 1 + byte consumption 1), and
   expanded length 1. Add one PE followed by a body GE: attempts boundary 2,
   no reset at End. Use nested empty replacements to prove nested spelling/
   comparison work and attempts matter even with no output, and the existing
   non-BMP boundary to retain byte semantics. Include one generated element
   that hits ParserState depth before publication. Do not assert that all
   intermediate native counters roll back on a later error; require bounds,
   preserved already-spent values and terminal Reader behavior.

5. **Q5 — references and local lexical limits.** `&e;` needs 3 raw/scratch bytes
   and native reference work 9; test all three in isolation. Include an outer GE
   whose replacement references a longer entity name to fail in replacement
   coordinates after a shorter physical reference succeeds. Generated `<a/>`
   needs local raw/scratch 4 and local work 8; parser/global/scratch-slot
   ceilings must remain larger. Repeat an entity to prove local/reference
   counters survive source switches. Cover the split-token rule with a
   nine-byte physical prefix + General reference (separate limits), compared
   with five prefix bytes + `&#65;` (ten bytes in one Text token).

6. **Q6 — aggregate scratch.** For fresh physical tokenizer raw/decoded limit
   16, local raw/decoded limit 8, and reference raw/scratch 4, required slot sum
   is **28**. Isolate input slot 15/16/17, replacement slot 7/8/9, total 27/28/29;
   keep unrelated totals generous when changing a slot. Test raw/scratch
   reference minima 10/4 and 4/10 with the same reserved 4. Force checked
   addition overflow using a usize::MAX slot and a nonzero second slot.
   All failures occur on the read after held DTD End; End stays the last origin.
   Existing lower-layer retained/reconfigured UTF-16 capacity controls remain
   lower-layer tests: stable Reader cannot accept a foreign retained tokenizer,
   so do not add a Reader seam just to smuggle one in.

7. **Q7 — global vs native work.** Use literal action journals, not a generous
   run's measured counters as the expected boundary.
   Stable `<!DOCTYPE r><r/>` spends **36** DTD work (12 scan + 12 unit parse +
   12 catalog) and **12** body work (4 scan + 4 validation + 4 semantic precharge),
   so full-document global boundary is **48**.
   Test declarations.max_work and text.max_work separately at 47/48/49;
   a larger Text cap must not raise the inherited declaration cap.
   Text cap 35 rejects body construction after returned Begin/End with
   C Text(Work); cap 36 constructs but has no body allowance, yielding C Work.
   Pair native scanner/catalog/frame/reference/local Work failures with a
   larger global allowance, then invert the cap to force global Work.
   Pre-cap components and retain documented tie precedence; do not reset shared
   scratch or native histories. A GE checkpoint control can use the documented
   extra 23 body work through Start + generated 'x' for e='x', independently
   accounting for stable DTD inheritance (not owned-stream raw-copy costs).

8. **Q8 — ownership and precedence.** The repeated-PE comment document above
   promotes 16 raw bytes total; test declaration raw-owned 15/16/17 separately
   from Parser owned-output 15/16/17, keeping the other allowance generous.
   Physical units spend zero promotion budget. Retain/drop earlier returned
   units and prove neither cumulative allowance is refunded.
   Keep existing Text `&amp;` ownership boundary 5 and changed stable attribute
   materialization boundary 64; those different policies are intentional.
   Add small collision rows: scanner Work before unit/scratch growth, unit byte
   grammar rejection before token growth, malformed generated grammar before
   raw promotion, Reference Work before reference Bytes/Scratch, and native
   ExpandedBytes before final ValueBytes while matching. Missing/unavailable
   refs in a stable attribute must still fail before a deferred output
   allocation; a matching prefix does not bypass validation.

Each group's literal expected thresholds, accepted prefix rows and complete
error shape are frozen before implementation runs. Byte lengths may be counted
from the literal fixture; token/work semantics require the action journal or
existing independent lexical oracle. Do not discover a passing ceiling by
running the same implementation and then call it independent evidence.

## Error, origin and stickiness assertions

Every failing row must assert:

- Exactly which constructor/read fails and which earlier events were returned.
  No rejected item/tag/partial Text is exposed. Held End and General-prefix
  delivery retain their established ordering.
- Typed SessionError branch and nested limit kind; physical_offset, local_offset,
  value_location and error origin shape where present. DTD physical grammar
  errors add the unit-relative offset once; replacement diagnostics retain the
  outer physical reference plus local bytes. Catalog replacement entity identity
  can be checked by its existing index getter; do not forge names or public IDs.
- Accepted physical high-water independently from error_offset. Physical byte
  exhaustion stops before the excluded byte; scanner append limits reject an
  unconsumed byte; tokenizer token errors can include the offending byte in
  accepted progress; reference classification Work can fail at the reference
  anchor after its closing semicolon was accepted. There is no universal
  position = error offset rule.
- Last delivered origin/range equals the literal prior successful row. Capture
  that expectation before the failing call; do not snapshot an already-cleared
  origin after failure and merely compare it with itself.
- Three repeated read_event errors equal the first complete error, with unchanged
  position/origin/range and available counters/phase identity. Existing counters
  suffice; do not add mutable catalog/frame/Budget accessors. Preserve generated
  error identity where an earlier event from that occurrence exists.
- Exact/one-above controls reach their documented checkpoint or EOF and repeat
  EOF without new work. Constructor failures have no mutable Reader to retry.
  into_inner after success, early stop and failure returns the original bytes
  without draining. The same case with BOM shifts physical ranges by 3 and
  leaves replacement-local ranges unchanged, for representative DTD/body cases.

For work attribution, controller and content cap catalog/frame native work at
usage + global remaining, synchronize committed deltas on failure as well as
success, and relabel native Work only when the global cap caused it. Native
reference/local failures remain nested Text errors; active shared Text Work is
Content Work. Body-constructor Text Work is deliberately a different shape
because the ledger cannot be adopted with spent work above its new ceiling.
Physical Text/reference failures may have no error origin, whereas generated
ones retain occurrence/local context. Assert current explicit contracts rather
than forcing all diagnostics into one generic XML limit error.
