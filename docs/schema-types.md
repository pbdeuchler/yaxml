# Schema datatypes and regular expressions

The shared foundation for XML Schema and RELAX NG validation.

- `yaxml::regexp::Regex` reimplements libxml2 2.15.4 `xmlRegexpCompile` and
  `xmlRegexpExec`: XML Schema 1.0 Appendix F syntax with libxml2's extra
  escapes (`\uXXXX`, `\!`, `\"`, `\#` and the other punctuation escapes).
  `Regex::new` uses `DEFAULT_BUDGET` (100,000 units); `with_budget` takes
  another. `is_match` matches the whole string.
- `yaxml::schema_types` reimplements `xmlschemastypes.c` for the 45 built-in
  types: `Type::parse` (`xmlSchemaValidatePredefinedType`), `Value::compare`
  (`xmlSchemaCompareValues`), `Value::equals` (`xmlSchemaAreValuesEqual`),
  `Facet::new` (`xmlSchemaCheckFacet`) and `Facet::check` (the validator's
  facet checks). `QName`, `NOTATION`, `ENTITY` and `ENTITIES` consult a
  caller `Context` for namespaces, notations and unparsed entities.

```rust
use yaxml::schema_types::{Comparison, Facet, Type};

let value = Type::Decimal.parse(" 1.50 ", None)?;
let bound = Type::Integer.parse("2", None)?;
assert_eq!(value.compare(&bound), Comparison::Less);
let facet = Facet::new("totalDigits", "2", Type::Decimal, None).unwrap();
assert!(facet.check(&value, "1.50"));
# Ok::<(), yaxml::schema_types::InvalidValue>(())
```

## Matching and resource bounds

A pattern compiles to a Thompson NFA. Every instruction, every copy made for
a counted repetition `{n,m}` and every range of a distinct character class
spends one budget unit, so `.{2147483647}` or `((a{1000}){1000})` fail with
`Error::TooComplex` instead of expanding. Groups and class subtractions nest
at most 50 deep (libxml2 limits groups only). Matching runs a lazily built
DFA over character classes with a 1 MiB cache that is discarded and rebuilt
when full; a character costs one table lookup, or one NFA step bounded by the
automaton size on a miss. Nothing backtracks, so `(a*)*b` on 200,000 `a`s
takes milliseconds. `cargo bench --bench regexp` (Apple M-series, release):
374 MB/s for `[a-z]*`, 373 MB/s for a ten-way alternation loop, 389 MB/s for
`(\p{L}|\s|\p{P})*` and `[\i-[:]][\c-[:]]*` over mixed text, 418 MB/s for
`(.*a){8}.*`.

Unicode categories and blocks come from libxml2's own Unicode 4.0.1 tables
(`src/regexp/unicode.rs`, generated by `tooling/gen_unicode.py` from
`codegen/unicode.inc` and `codegen/ranges.def`), including their quirk that
UnicodeData first/last ranges contribute only their endpoints: `\p{L}`
matches U+4E00 but not U+6F22. `\i` and `\c` use XML 1.0 4th edition names,
as libxml2 does; NCName and friends use 5th edition names.

## Kept libxml2 behavior

- Regex syntax: `{n,0}` means `{n}`; `{n,m}` with `m < n` matches nothing;
  a maximum of `2147483647` is unbounded; `{` and `}` alone are literals; a
  `-` inside brackets that neither starts the group nor precedes `]` is
  skipped (`[a-c-e]` is `[a-ce]`); a subtracted group starting
  with `^` is added instead (`[a-z-[^aeiou]]` is `[a-z]`); `\P{..}` inside brackets is not negated;
  `\p{Cn}` matches nothing; patterns end at NUL.
- Datatypes: libxml2's whitespace pre-normalization, `0.` but not `.` as a
  decimal, `1e` and `1e+` as floats, base64 ignoring characters outside its
  alphabet, empty `IDREFS`, no year zero, `24:00:00` as end of day, and an
  unprefixed `NOTATION` taking no default namespace.
- Ordering: floating-point seconds; durations compared through month
  ranges; libxml2's partial order for zoned against unzoned values (the
  ±14:00 shifts are no-ops for unzoned values), its gDay/gYearMonth mask
  sharing, times shifted to UTC landing in year 1 (`13:20:00-05:00` is after
  `18:20:00Z`), `24:00:00` ordered on its own day, `NaN` equal to itself and
  above every number, unequal `string` values indeterminate, the inverted
  `token`/`normalizedString` order of differing non-blank bytes, and
  `' '` against `'"'` in two collapsed strings being incomparable (the raw
  byte difference collides with libxml2's error code -2).
- Facets: lengths of `QName` and `NOTATION` always pass; types without a
  length (numbers, dates) measure 0; facet counts saturate like `strtoul`.

## Intentional differences

- `\p{IsX}` with an unknown block is a syntax error; libxml2 compiles it and
  then fails (or, inside brackets, matches everything) at match time.
- Counted repetition is expanded under the budget instead of counted, so
  very large counts are rejected (libxml2's `test/regexp/bug783015`).
- libxml2's determinism check applies the negation of `\P` twice, marks
  transitions deterministic that are not, and then drops the backtracking
  points it needs: `(b*)\P{Nd}` fails on `b` there and matches here.
- libxml2 aborts a match after 10 million backtracking pushes with an error;
  this engine never backtracks. Inputs with non-XML characters do not match
  (libxml2 returns an error).
- Values are UTF-8 Rust strings; there are no canonical-value
  (`xmlSchemaGetCanonValue`) or list-value APIs yet, and the progressive
  `xmlRegExec*`/`xmlAutomata*` interfaces are not implemented.

## Fuzzing

`tests/support/fuzz/regexp.rs` checks syntax error offsets, budget monotonicity,
cache-independent results, and that `(P)*` and `(P)|literal` accept what
they must. `tests/support/fuzz/datatypes.rs` checks normalization idempotence, list items,
reflexive comparison and equality, antisymmetry for totally ordered types,
and every facet kind. See [yaxml-harness/fuzz/README.md](https://github.com/pbdeuchler/yaxml-harness/blob/main/fuzz/README.md).
Two 330-second runs each on nightly-2026-06-06 (`-timeout=2`, ASan, the
second on the final code): `regexp` 209,811 and 213,575 executions, `datatypes`
6,531,538 and 4,171,035, no crashes, timeouts or leaks; the minimized corpora
(`cargo fuzz cmin`) hold 898 and 3,710 inputs reaching 2,795 and 4,922 edges.
