# Compatibility catalogue and implementation order

This is a work inventory, not a claim of implemented compatibility. The baseline is **libxml2 2.15.4**, released 2026-09-04. Pin a source release, build options, and option combinations for every differential test; libxml2 behavior and available symbols vary by release and configuration. The [official release directory](https://download.gnome.org/sources/libxml2/2.15/) identifies this release. The [tagged headers](https://github.com/GNOME/libxml2/tree/v2.15.4/include/libxml) define the source API.

The adjacent [`libxml2-api.tsv`](libxml2-api.tsv) indexes **4,056 identifiers** across the 46 tagged public header/template files. Four compatibility headers contain no API declarations and have explicit `empty_header` rows. This document groups the required behavior and orders implementation. Nothing below is implicitly out of scope because it is low priority.

Each row also carries a `status` and a `rust` column (roadmap item 20), generated by `tooling/api_status.py` from naming rules plus an explicit override table, and refreshed with `uv run --no-project tooling/api_status.py` (needs the libxml2 2.15.4 source for numeric error codes: `YAXML_LIBXML2_SOURCE`). `implemented`: a yaxml API provides the behaviour; `partial`: some of it, or only the error category without libxml2's numeric code; `not-started`; `not-applicable`: a Rust API intentionally replaces it (`Drop`, no global state, `std` types); `removed-upstream`: deprecated or removed in 2.15. For `implemented` and `partial` rows `rust` lists the yaxml paths (`Type::member`, `module::item`, enum variants, `pub` fields) and an optional ` - note`; for the other statuses it gives the reason or the nearest API. `tests/api_inventory.rs` (and `tooling/api_status.py --check`) fail when a claimed path no longer exists in `src/`, so the inventory cannot drift silently. ## Meaning of replacement

1. **Behavioral replacement:** equivalent XML results, events, mutations, queries, serialization, validation, and failure classification through a safe Rust API.
2. **Source migration:** familiar operations and option mappings with explicit ownership and errors. C function names are a migration index, not the recommended Rust interface.
3. **Binary replacement:** exported C symbols, ABI layouts, ownership, callbacks, global variables, allocator hooks, variadic functions, and direct mutable struct fields. This cannot be implemented faithfully by a crate that forbids unsafe: arbitrary foreign pointers cannot be dereferenced safely. Treat this as a separate future adapter with its own policy decision, not an achieved property of the safe core.

Python, Ruby, JavaScript/TypeScript, and Go bindings should target owned document handles and document-scoped node identifiers. Foreign references must keep their document alive; deletion must reject stale handles. Avoid exposing the internal tree layout. WebAssembly with copied inputs/results offers one binding route without requiring unsafe Rust in this crate. Native runtime adapters ordinarily need dependencies and unsafe foreign interfaces outside the core.

The implemented subset now includes the borrowing slice reader, read-only DOM,
callback `PushParser`, bounded lending `BufferedReader`, owned trees, UTF-8 event
writing, complete borrowed/owned DOM serialization, libxml2 `xmlsave` output
(`save`: options, encodings, subtrees, regenerated DTD; [writer.md](writer.md)),
bounded owned-value editing,
rooted document creation, fresh element/leaf insertion, permanent subtree removal, an explicit `Read`
adapter, the [`TextReader`](textreader.md) node cursor, [XPath 1.0](xpath.md) evaluation and [canonicalization](c14n.md) over both DOMs, and [XInclude/XPointer](xinclude.md). Input shares XML 1.0 grammar, including the
internal DTD subset (below); owning/streaming input
also supports [UTF-16 and declared US-ASCII, ISO-8859-x and windows-1252](encoding.md). See the [streaming contract](streaming.md)
for event lifetimes, limits, cancellation and incremental error ordering. The
full upstream reader/SAX option surfaces remain open.

`Node::text_chunks()` and `OwnedNode::text_chunks()` provide allocation-free
string-value pieces for supported node kinds. Containers concatenate descendant
Text/CDATA logically; comment and PI leaves expose their own data. Joining the
pieces matches `xmlNodeGetContent` on the bounded [pinned oracle cases](archive/validation-text-chunks.md).
The methods retain chunk boundaries and include the content of kept entity
references; they do not add attribute nodes or the allocating C entry point.

## Document type declarations

Every parser reports one `Event::Doctype` (DOM: `NodeKind::Doctype` /
`OwnedNodeKind::DocumentType`, `doctype()`) with the name, unquoted public and
system identifiers and the exact internal-subset text. The internal subset is
processed: parameter entities, general entity expansion in content and
attribute values (re-tokenized, so replacement markup becomes events; kept as
references without `NOENT`, see [option compatibility](#entity-references-without-noent)),
default and `#FIXED` attributes (with `DTDATTR`), and tokenized
attribute-type normalization.

External resources load only through a caller `Resolver` in `ParseOptions`
(`ParseOptions::with_resolver`), and only what the flags request: the external subset after the internal subset with
`DTDLOAD`, `DTDATTR` or `DTDVALID`, external parameter entities where
referenced between declarations with those or `NOENT` (inside an entity
value only with `NOENT` or `DTDVALID`, as `xmlExpandPEsInEntityValue`), and external parsed general entities on
first reference in content with `NOENT` or `DTDVALID`; `NO_XXE` loads
nothing. Each loads at most once and is cached. System IDs resolve with `uri::resolve` against the declaring
resource's base, starting from the caller's document base. Resources decode
by BOM or text declaration (UTF-8/16, single-byte charsets), normalize line
ends and drop the text declaration. External DTD text supports conditional
sections and parameter references inside declarations. Declining
(`Ok(None)`) matches libxml2's missing-file warning: the subset is skipped and
the reference expands to nothing. A resolver `Err` whose
`diagnostic::io_code` is `XML_IO_UNKNOWN` (any `io::Error::other`) or
`XML_IO_ENOENT` declines the same way, as `xmlCtxtErrIO` skips those; any
other `Err` is fatal `ExternalResource`. Unlike libxml2, a declined resource
records no warning in `errors()`. A resource the flags do not request is declined without calling
the resolver; `NONET` is the default because nothing has network access unless
the caller's resolver provides it. Like libxml2, a
standalone document cannot use externally declared general entities, a
DeclSep PE must hold whole declarations, and a text declaration's version
must be 1.0.

`Document::element_by_id`/`OwnedDocument::element_by_id` (`xmlGetID`) and
XPath `id()` use `xml:id` and attributes declared `ID`, first element in
document order per value. Unlike libxml2, attributes on elements produced by
entity replacement also count. `ids()` on both DOMs lists the table itself (`xmlIDTable`):
`(element, attribute position)` for every ID attribute, sorted by element,
a repeated value listed again where libxml2 keeps only the first.

The default follows `xmlReadMemory(..., 0)`: references are kept and only
defaulted namespace declarations apply; `NOENT | DTDATTR` gives the
substituted tree with default attributes that XML 1.0 §5.1 describes for
non-validating processors (the default before parser options existed). Undeclared-entity
handling mirrors libxml2's `xmlHandleUndeclaredEntity`: once any PE reference
or an external subset is seen and the document is not `standalone='yes'`, an
undeclared general or parameter entity is dropped with `NOENT` and kept as an
empty reference without it (libxml2 reports a recoverable error), and
references to unloaded external entities expand to nothing or stay empty
references the same way (libxml2's failed or skipped load). Otherwise `UnknownEntity` is fatal. Like
libxml2, declarations after an unread PE reference are still processed.
Unparsed entities in content (`UnparsedEntity`), external entities in attribute
values (`ExternalEntityInAttribute`), recursion (`EntityLoop`), unbalanced
replacement markup (`UnbalancedEntity`) and malformed declarations
(`InvalidDtd`) are fatal. Ceilings are `Limits::max_dtd_bytes`,
`max_entity_expansion_bytes`, `max_entity_amplification`,
`max_entity_references` and `max_entity_depth`.

Amplification follows libxml2's `xmlParserEntityCheck` without
`XML_PARSE_HUGE`: every entered replacement text (general, parameter and
external entities, in content, attribute values and the subset) and every
copied default attribute is charged its length plus a fixed cost of 20; the
total may exceed `max_entity_expansion_bytes` (default 1,000,000, libxml2's
`XML_PARSER_ALLOWED_EXPANSION`) only up to `max_entity_amplification`
(default 5, `XML_MAX_AMPLIFICATION_DEFAULT`) times the input consumed so far,
resolver bytes included. Expansion work is O(1) amortized per charged byte, so
billion-laughs, parameter-laughs and quadratic-blowup documents fail in
milliseconds with `LimitExceeded(EntityExpansion)`; `tests/amplification.rs`
asserts the per-use cost is constant on all five parsers.

Known differences from the pinned oracle, all intentional: PE references
inside internal-subset markup are fatal as the WFC requires; a `&#13;` in
replacement text stays CR in content (libxml2 parses entity text as new input
and turns it into LF); `Writer` writes the DOCTYPE exactly as parsed, while
`save` regenerates declarations as libxml2 does; libxml2 reloads an
external PE per reference where yaxml caches it. The differential cases live in `tests/dtd.rs`
(`YAXML_XMLLINT=... cargo test --test dtd -- --ignored`).

The [owned edit API](owned-dom.md#editing-existing-values) replaces literal leaf
and existing ordinary-attribute values by checked handle. Value edits preserve
topology. [Structural edits](owned-dom.md#leaf-insertion-and-permanent-removal)
append fresh Text/CDATA/comment/PI leaves and permanently remove non-root
subtrees. Text/CDATA require an element parent; comments/PIs also append to the
document epilog. PI targets and lexical payloads are validated before allocation.
The `append_*` creators never merge Text nodes; removal makes every subtree handle stale and
protects the document element and synthetic root. Parsed survivors retain source
provenance and created nodes have none. Creation and pool-work counters persist
across editors without refunds. [Rooted construction](owned-dom.md#creating-documents-and-elements)
also creates a complete document or appends a fresh empty element with ordered
initial attributes and declarations. Exact prefixes are preserved; automatic
prefixes follow a bounded deterministic policy. Each element retains one
contiguous attribute range. [Moves](owned-dom.md#moving-unlinking-and-replacing)
follow `xmlAddChild` (with its Text merging), `xmlAddPrevSibling`,
`xmlAddNextSibling`, `xmlUnlinkNode` (detached subtrees keep live handles) and
`xmlReplaceNode`; [attribute, name and declaration edits](owned-dom.md#attributes-names-and-declarations)
follow `xmlSetNsProp`, `xmlUnsetNsProp`, `xmlNodeSetName`/`xmlSetNs` and
`xmlNewNs`. Unlike libxml2, every edit keeps prefixes declared where they are
used ([namespace consistency](owned-dom.md#namespace-consistency)); `compact`
reclaims edit garbage without renumbering handles. Copy/import/adoption, slot
reuse, entity-interpreting setters and C entry points remain open. The header inventory
remains an unmapped upstream catalogue, not a claim that these Rust methods
provide full `tree.h` compatibility.

Recorded parsing differences include encoding agreement (a BOM-less UTF-16 source
still requires a declaration with an encoding) and namespace URIs. Namespace URI syntax is not validated: an exploratory
2.15.3 run with `--strict-namespace` rejected `xmlns='urn:中'`, which yaxml
accepts. That observation applies to both UTF-8 and UTF-16; it is not a pinned
2.15.4 result. Encoding corpus fixtures use ASCII namespace URIs to isolate
decoding, and this URI-validation gap remains part of the compatibility burndown.
Single-byte decoding follows libxml2 built without iconv/ICU but with
`LIBXML_ISO8859X_ENABLED`; the pinned oracle build disables ISO8859X, so it
reports ISO-8859-2..16 as unsupported while yaxml decodes them. A UTF-8 BOM
with a single-byte label is rejected where libxml2 warns and continues as UTF-8.

A `#` in a system literal is an error only in an `<!ENTITY>` declaration's
system identifier ("Fragment not allowed", as libxml2's `xmlParseEntityDecl`
reports it). DOCTYPE and NOTATION system identifiers may contain one (XMLTS
`oasis/p11pass1.xml`).

## DTD declaration model

`valid::Dtd` (`Document::dtd`, `OwnedDocument::dtd`, `valid::Dtd::load` and
`parse`) has read-only views that borrow the parser's own declaration
storage: `entity` (`xmlGetDocEntity`, falling back to
`valid::predefined_entity`), `parameter_entity` (`xmlGetParameterEntity`),
`element` (`xmlGetDtdElementDesc`), `attribute` (`xmlGetDtdAttrDesc`),
`notation` (`xmlGetDtdNotationDesc`) and the iterators `entities`,
`elements` (with `Element::attributes`) and `notations` in declaration
order. `valid::Entity` carries libxml2's entity type (`EntityKind`, the
`xmlEntityType` numbers), name, `content`, `original` (the literal as
written, libxml2's `orig`), public and system identifiers,
`uri`, the `NDATA` notation and whether the external subset declared it
(`xmlGetDtdEntity` is `entities()` filtered on `external_subset`).
`valid::Element` has `ContentKind` (`xmlElementTypeVal`) and the content
model as `xmlDumpElementDecl` prints it; `valid::Attribute` has
`AttributeKind` (`xmlAttributeType`), `AttributeDefault` (`xmlAttributeDefault`
with the value) and the enumeration. `valid::value_matches(kind, value)` is
the validator's lexical check (`xmlValidateNameValue`, `NamesValue`,
`NmtokenValue`, `NmtokensValue` as `Id`, `IdRefs`, `NmToken`, `NmTokens`). `save::encode_entities`
(`xmlEncodeEntitiesReentrant`, with `save::Escape` standing for the document
argument: `Xml` with an encoding, `Ascii` without one or without a document,
`Html`) and `save::encode_special_chars` (`xmlEncodeSpecialChars`) reuse the
serializer's escaping tables. `save::notation_table` is `xmlDumpNotationTable`
(still used by lxml), in declaration order where libxml2 writes hash order.
`yaxml::chars` holds the `chvalid.h`
predicates: `is_char`, `is_blank`, `is_pubid_char` (the parser's own Fifth
Edition classes) and `is_base_char`, `is_ideographic`, `is_combining`,
`is_digit`, `is_extender` (XML 1.0 Fourth Edition Appendix B, generated with
the regexp tables by `tooling/gen_unicode.py` from libxml2's
`codegen/ranges.def`). Each takes a `u32`, `char` or `u8`, which covers the
function, `Q` and `_ch` forms.

`Editor::add_declarations(markup)` adds declarations to an owned document
(`xmlAddEntity`, `xmlAddElementDecl`, `xmlAddAttributeDecl`,
`xmlAddNotationDecl`; `xmlCreateIntSubset` when there is no DOCTYPE): the
markup is read as more of the internal subset, after the declarations the
document has, and saved with it; `OwnedDocument::is_id` is `xmlIsID`.
Declarations are given as markup rather than one call per C struct.
`Editor::set_internal_subset(markup)` replaces the internal subset's
declarations (what freeing declaration nodes and adding new ones does),
`Editor::remove_doctype` unlinks and frees `intSubset`, and
`Editor::set_doctype_ids` sets `ExternalID` and `SystemID` (output pinned
against libxml2 2.15.4 in tests/declarations.rs). Declarations from a loaded
external subset survive these edits, after the internal ones; an external
declaration that an internal one shadowed when the document was read was
dropped then and does not come back (libxml2 keeps it in `extSubset`).
Detached DTDs and declarations (`xmlNewDtd`, `xmlNewEntity`) do not exist.

Differences from libxml2, by design:

- yaxml keeps one table for both subsets, the first declaration of a name
  winning. A name both subsets declare is found only as declared internally,
  so `xmlGetDtdEntity` (external subset only) has no counterpart for it.
- `content` is also the text of an external entity the parser loaded;
  libxml2 parses external general entities into children and stores
  external parameter entity text only under `NOENT` or `DTDVALID`.
- Stored entity values have normalized line ends; libxml2 stores CR as read
  and normalizes when the text is parsed.
- Without a resolver nothing has a base, so `uri` is the system identifier
  (libxml2 resolves it against the file name).
- `encode_*` escape a NUL as `&#xFFFD;`; libxml2's C strings end there.

Differential: `harness/tooling/libxml2_dtd.c` dumps both subsets of every document
through libxml2's tables, the lookups of every declared name and the
character classes and escapers; `tests/dtd_oracle.rs` compares them with the
views after merging libxml2's subsets as above and counting the accepted
classes:

```
O=../yaxml-oracle   # pinned libxml2 2.15.4 source and build
cc -std=c11 -Wall -Wextra -Werror -Wno-deprecated-declarations -I$O/build \
  -I$O/libxml2-2.15.4/include harness/tooling/libxml2_dtd.c $O/build/libxml2.a \
  -lm -lz -liconv -o target/dtd-helper
YAXML_DTD_HELPER=$PWD/target/dtd-helper cargo test --release --test dtd_oracle -- --nocapture
```

Last run (2026-10-19): the eight classes agree on all 1,114,112 code points
and the six byte macros on all 256 bytes; the escapers on 2,131 strings in
all four modes; declarations on all 410 parsed documents of libxml2's
`test/valid` and the XMLTS valid cases with `DTDLOAD` (10,586 declaration and
lookup lines; 17 external texts, 12 CR values and 11 both-subset lookups
accepted) and all 403 with `DTDLOAD | NOENT` (10,506 lines; 53, 16 and 11).
The comparison found one parser difference, now fixed: libxml2 expands an
external parameter entity inside an entity value to nothing unless `NOENT` or
`DTDVALID` asks to load it (`xmlExpandPEsInEntityValue`), where yaxml loaded
it under `DTDLOAD` alone. The `dtd` fuzz target checks that each view is
consistent with its kind and lookup, that stored entity text and printed
content models are fixed points of redeclaration, and that escaped text
reparses to itself.

## Prioritized feature map

Status audit 2026-10-19 against `src/`, `tests/` and the module docs; numbers come from the docs or from `cargo test --all-targets -q` (932 passed, 0 failed, 22 ignored) and `harness/examples/xml_conformance` run as in CLAUDE.md's gate. `Not started` marks work with no code.

Priority is dependency order and migration value. P0 is the first usable secure XML subset; P1 adds true buffered streaming and ordinary editing/output; P2 enables XML document-processing stacks; P3 covers HTML, schemas and legacy clients; P4 adds language adapters.

| P3 | Legacy process/thread globals, initialization/cleanup, memory debugging and callbacks, dynamic modules, removed HTTP/FTP compatibility stubs, build/version/export macros. **Not started, mostly by design**: the crate keeps no global state, so `xmlInitParser`/`xmlCleanupParser`, `globals.h`, `threads.h`, `xmlmemory.h` callbacks and `xmlmodule.h` have nothing to port; the removed HTTP and FTP clients stay out; version constants and `xmlCheckVersion` live in `yaxml::features` (see the I/O row); the build macros (`xmlversion.h` `LIBXML_*_ENABLED`) map to `Feature` | `globals.h`, `threads.h`, `xmlmemory.h`, `xmlmodule.h`, `nanohttp.h`, `nanoftp.h`, `xmlversion.h`, `xmlexports.h` |
| P4 | Language adapters and migration packages: document/node ownership, byte/text conversion, structured exceptions, iteration, cancellation, cleanup and batching across runtime boundaries. **Not started**: [bindings.md](bindings.md) is a design outline and no binding crate exists; the core prerequisites exist (`OwnedNodeId` handles, `TextReader`, `allocator_api`, `ErrorKind` mapping); a C ABI or any unsafe adapter needs owner sign-off | Python, Ruby, JavaScript/TypeScript, Go; separate from safe-core dependencies |

The whole surface includes callbacks, enum values, macros, typedef aliases and public struct members, not just functions. Exact function signatures and member layouts remain available in the pinned headers; the TSV is an index rather than a C header replacement.

## Option compatibility

`yaxml::ParseOptions` is the one options value of every XML parser and DOM:
`flags` (libxml2's `xmlParserOption` bits, the constants in `yaxml::options`
with libxml2's values), `limits`, `decode_limits`, `base` and `resolver`.
`Reader::with_options`, `PushParser::with_options`,
`BufferedReader::with_options`, `TextReader::with_options`,
`Document::parse_with` and `OwnedDocument::parse_with` take it; the older
constructors (`new`, `parse`, `with_limits`, ...) are conveniences for the
default options, and there is no other resolver entry point. Unknown bits and every flag a
surface lacks fail with `ErrorKind::UnsupportedOption` before parsing; a flag
is accepted without code only where libxml2 2.15.4 gives it no observable
effect on results. A flag whose implementation a disabled cargo feature
compiles out is unsupported everywhere: `XINCLUDE` without `xinclude`,
`CATALOG_PI` without `catalog` (and the save flag `AS_HTML` without `html`;
README.md#cargo-features). `tests/options.rs` covers each row; the `dom`, `owned` and
`dtd` fuzz targets select flags from a leading high-bit byte
(`tests/support/fuzz/options.rs`).

| Flag | Status |
| --- | --- |
| `RECOVER` | Build what is parsable of a malformed document and list the errors (`errors()`), on the DOMs and every stream; see [Recovery](#recovery-recover). |
| `NOENT` | Substitutes general entities (no `EntityRef` nodes or `EntityStart`/`EntityEnd` events); with a resolver loads external parsed entities and parameter entities. |
| `DTDLOAD` | With a resolver, loads the external subset and external parameter entities. |
| `DTDATTR` | Adds non-namespace default attributes (defaulted `xmlns` declarations always apply, as in libxml2); implies `DTDLOAD`. |
| `DTDVALID` | DOMs: validates after parsing; `Document::validity`/`OwnedDocument::validity` hold the diagnostics. `TextReader`: validates while reading (`dtd_diagnostics`). Loads the subset and external entities (unless `NO_XXE`). Rejected by the other streams (`valid::StreamValidator` validates their events). |
| `NOERROR`, `NOWARNING` | Accepted: they only silence printed reports in libxml2; yaxml prints nothing and returns diagnostics. Warnings are kept in `errors()` regardless ([Warnings](#warnings)). |
| `PEDANTIC` | Adds libxml2's pedantic warnings to `errors()`: `LangValue`, `EntityRedefined` and `RelativeNamespaceUri` for a prefix ([Warnings](#warnings)). |
| `NOBLANKS` | DOMs: drops ignorable whitespace text with libxml2's `areBlanks` rules (DTD element content, `xml:space`, text kept earlier in an element without `xml:space`, sibling heuristic, which never drops text before an entity reference). `TextReader` drops them as libxml2's reader does, deciding when the text is queued (`TextReader::with_options`; [textreader.md](textreader.md)), and `PushParser` and `BufferedReader` drop the text events by the same rules ([streaming.md](streaming.md#recovery-and-blanks)); rejected by `Reader`. |

Only declarations equivalent to the predefined ones are kept, so without NOENT the reference becomes an entity-reference node instead of text. Supporting it would add a DTD lookup in front of every predefined reference in the tokenizer, attribute values and recorded expansions. |
| `XINCLUDE` | `OwnedDocument::parse_with`: processes XInclude through the same resolver (`xinclude::process`); failures are `ErrorKind::XInclude`. Rejected by the borrowed DOM, streams and `TextReader`. |
| `NONET`, `NO_SYS_CATALOG` | Accepted: nothing touches the network and there is no system catalog. |
| `NODICT`, `COMPACT`, `BIG_LINES` | Accepted: storage layout only; positions are byte offsets. |
| `NSCLEAN` | Drops a namespace declaration that rebinds a prefix to the URI it already has (every surface). |
| `NOCDATA` | Reports CDATA sections as text, merged with adjacent text in trees (every surface). |
| `NOXINCNODE` | Accepted: XInclude never adds start/end marker nodes. |
| `OLD10` | XML 1.0 Fourth Edition names (the Appendix B classes of `yaxml::chars`) on every surface: element and attribute names, PI targets, the DOCTYPE name and every name and enumeration token a declaration holds, in the internal subset, the external subset and parameter entities; a version other than 1.0 is fatal (`InvalidDeclaration`, libxml2's `XML_ERR_UNKNOWN_VERSION`). Fourth Edition names are a subset of Fifth Edition names with the same ASCII, so only non-ASCII names are checked again. Under `RECOVER` a content name ends at its first invalid character, as libxml2's does, and documents are `properties::OLD10`. Not applied: `DTDVALID` checks of Name and Nmtoken attribute values (libxml2 uses `XML_SCAN_OLD10` there), repairs inside the DTD (the DTD stack never repairs), and the diagnostic re-reader (Fifth Edition rules). All 313 historical-edition XMLTS cases agree with `xmllint --oldxml10` on acceptance (305 of them are rejected only under the flag), and so do 22 hand-written cases with and without `--recover` but one (a recovered DOCTYPE name). `tests/old10.rs`. |
| `UNZIP` | Accepted with no effect, as in libxml2 built without zlib (`features::has(Feature::Zlib)` is false; the oracle build too). Compressed input is declined ([remaining-work.md](remaining-work.md)). |
| `CATALOG_PI` | Every surface passes a `<?oasis-xml-catalog catalog="URL"?>` outside the DTD to `Resolver::catalog_pi`; only `catalog::CatalogResolver` acts on it ([catalog.md](catalog.md#document-catalogs-catalog_pi)). |
| `NOBASEFIX` | With `XINCLUDE`, no `xml:base` fixup. |
| `HUGE` | Raises token and DTD ceilings to 1 GB, depth to 2048 and entity depth to 40 (default 20) (libxml2's huge values); larger caller limits stay. `max_events`, `max_total_attributes`, `max_owned_bytes` and `max_input_bytes` have no libxml2 counterpart and are unchanged ([security.md](security.md#defaults-against-libxml2-2154)). |
| `IGNORE_ENC` | Ignores the declared encoding: UTF-8 (or the BOM-detected encoding) is kept, and the label is not recorded as the document encoding (BOM-detected: kept, or "UTF-8" on mismatch). |

| `NO_XXE` | Never loads the external subset or external entities, even with a resolver. |
| `SKIP_IDS` | DOMs record no ID attributes (`element_by_id`, XPath `id()`). |

### Warnings

libxml2's default-on parser and namespace warnings (`xmlWarningMsg`,
`xmlNsWarn`, and the `XML_WAR_*` codes raised through `xmlNsErr` or
`xmlErrMsgStr`) are kept like namespace errors: on every surface, strict or
`RECOVER`, in `errors()` under the same cap, never stopping a parse. Each is
an `ErrorKind::Warning(yaxml::Warning)`; `describe` gives libxml2's domain,
code, level, column and message (`tests/namespace_errors.rs`, checked against
`xmllint` 2.15.4). A consumer that rejects any libxml2 diagnostic (librsvg)
rejects a non-empty `errors()`; one that wants libxml2's error status filters
on `Diagnostic::level`.

| Warning (libxml2 code, level) | Raised for |
| --- | --- |
| `UnknownVersion` (`XML_WAR_UNKNOWN_VERSION`, warning) | `version` other than `1.0` |
| `SpaceValue` (`XML_WAR_SPACE_VALUE`, warning) | `xml:space` other than `default`/`preserve` |
| `NamespaceUri` (`XML_WAR_NS_URI`, error: `xmlNsErr`, not namespace-well-formed) | a namespace name that is not a URI reference |
| `RelativeNamespaceUri` (`XML_WAR_NS_URI_RELATIVE`, warning) | a relative default namespace name; with `PEDANTIC` also a prefixed one |
| `LangValue` (`XML_WAR_LANG_VALUE`, warning; `PEDANTIC`) | an `xml:lang` value `xmlCheckLanguageID` rejects (RFC 3066/4646 shape) |
| `EntityRedefined` (`XML_WAR_ENTITY_REDEFINED`, warning; `PEDANTIC`) | a second internal-subset declaration of an entity (the first is kept) |
| `CatalogPi` (`XML_WAR_CATALOG_PI`, warning; `CATALOG_PI`) | an `oasis-xml-catalog` instruction whose data is not `catalog="URL"` (silent without `=` after `catalog`) |
| `ReservedTarget` (`XML_ERR_RESERVED_XML_NAME`, warning) | a PI target starting with `xml` (not `xml-stylesheet`/`xml-model`) |
| `EncodingMismatch` (`XML_WAR_ENCODING_MISMATCH`, warning) | a BOM or signature that disagrees with the declared label |
| `UndeclaredEntity` (`XML_WAR_UNDECLARED_ENTITY`; error with `NOENT`/`DTDLOAD`/`DTDATTR`) | an undeclared reference libxml2 does not make fatal (unread external subset or parameter entity), in content, attribute values and the internal subset |
| `PredefinedEntity` (`XML_ERR_REDECL_PREDEF_ENTITY`, warning) | an internal-subset declaration of `lt`, `gt`, `amp`, `apos` or `quot` with replacement text XML 1.0 section 4.6 does not allow; the declaration is dropped (not stored or saved) |
| `XmlIdValue` (`XML_DTD_XMLID_VALUE`, error) | an `xml:id` value (specified, or a `DTDATTR` default) that is no NCName once normalized and trimmed, as SAX2 checks it: not in entity content, not when the value keeps entity references (no `NOENT`), not when `DTDVALID` validates a DOCTYPE |
| `XmlIdType` (`XML_DTD_XMLID_TYPE`, error) | an `xml:id` attribute declared with a type other than `ID` (every definition, also under `DTDVALID`) |

Not matched: `EntityRedefined` inside the external subset (libxml2's `already defined in the external subset`); the I/O warning for an external
subset or entity that fails to load (`Ok(None)` from a resolver); warnings
inside the external subset, ATTLIST defaults and entity values; a strict
fatal error drops the warnings recorded before it (the parse returns only the
error); context lines of a warning inside entity content or a parameter
entity's replacement text. For an empty `xml:id` libxml2 also reports the ID
as already defined (a validity error it raises for the first empty ID); yaxml
does not, and it describes an `xml:id` default from the external subset with
an empty value (the re-reader sees only the internal subset). An editor's `add_declarations`/`set_internal_subset`
drops such a declaration without an error (libxml2's `xmlAddDocEntity` fails).

### Document properties

`Document::properties` and `OwnedDocument::properties` return libxml2's
`doc->properties` bits (module `yaxml::properties`), as
`xmlSAX2EndDocument`, `xmlNewDoc` and `xmlCopyDoc` set them: a parsed XML
document is `WELLFORMED` unless `RECOVER` recovered from an error, then
`NSVALID` without namespace errors (`Warning::NamespaceUri` included) and
`DTDVALID` unless `DTDVALID` validation failed, an undeclared entity was
referenced, or an element or notation was declared twice (libxml2 clears
`ctxt->valid` for those without validation too); parsed HTML is `HTML`;
`OwnedDocument::create` and every `try_clone` are `USERBUILT`, `html::create`
`HTML | USERBUILT` (`htmlNewDocNoDtD`). Edits leave
them unchanged. A parse with `XML_PARSE_OLD10` is also `OLD10`, even when
recovered. `XINCLUDE` and `INTERNAL` are never set. To keep
them exact past the 100-error cap, `errors()` still keeps the first error
clearing a bit, as libxml2 keeps the first fatal error. `tests/properties.rs`
pins these against values recorded from libxml2.

`parse_flags()` on both DOMs is `doc->parseFlags`: the `ParseOptions` (or
`html::Options`) flags as given, 0 for created and copied documents.

### Namespace errors

libxml2 reports namespace errors through `xmlNsErr`, which marks the document
not namespace-well-formed but leaves it well-formed: the parse succeeds
without `RECOVER` (`xmllint` exits 0 on `<r><p:c/></r>`). yaxml does the same
on every surface: `Document`, `OwnedDocument`, `Reader`, `PushParser`,
`BufferedReader`, `TextReader` and `Editor::parse_content` keep them in
`errors()` (`Fragment::errors`), with or without `RECOVER`, in the same list
and under the same 100-error cap as recovered errors. Each is an
`ErrorKind::Namespace` that `describe` gives libxml2's code and message.

| Error (libxml2 code) | Tree (libxml2 and yaxml) |
| --- | --- |
| Unbound element or attribute prefix (`XML_NS_ERR_UNDEFINED_NAMESPACE`) | The name keeps its prefix, in no namespace. |
| A Name that is not a QName, as `a:b:c` or `a:` (`XML_NS_ERR_QNAME`) | The name, unprefixed, in no namespace. |
| `xmlns:p=""`, `xml` or `xmlns` misused, the XML or XMLNS namespace name bound elsewhere (`XML_NS_ERR_XML_NAMESPACE`) | The declaration is dropped. |
| One expanded attribute name under two prefixes (`XML_NS_ERR_ATTRIBUTE_REDEFINED`) | Both attributes are kept. |
| A colon in a PI target, or in an entity or notation name in the internal subset (`XML_NS_ERR_COLON`) | Kept. |

A QName repeated in one tag (`xmlns:p` included) stays a fatal
`DuplicateAttribute`, as libxml2's `XML_ERR_ATTRIBUTE_REDEFINED` is. A name
in no namespace is its own local name, as libxml2 stores it: XPath
`local-name()` and name tests, RELAX NG and XML Schema matching, C14N
attribute order and `TextReader::local_name` see `p:c` (with no prefix), so
`<p:c/>` does not match a pattern for `c`. The checked `Writer` writes what
the parsers keep as read; an event it could not reparse as given (a
declaration the parser drops) fails with the namespace error. The Python
binding raises them as lxml does unless recovering. Against `xmllint` (with
and without `--recover`) on the 103 inputs of XMLTS, libxml2's `test/` and
`tests/namespace_errors.rs` for which it reports a namespace error, exit
status and output agree on all 103 in both modes (11 and 96 before),
messages on 76 and 77. Not matched:

- A defaulted declaration that cannot bind is dropped without an error;
  libxml2 binds it unchecked (keeping `xmlns:p=""`), except for `xml`.
  Without `DTDATTR`, defaulted attributes are not checked (libxml2 reports
  their unbound prefixes and duplicates).
- Entity content is read in each reference's scope, so its errors repeat per
  reference, and a prefix the reference's scope binds is not an error;
  libxml2 parses the content once. Colons in external-subset entity and
  notation names are not reported.
- A strict parse that stops returns only the error that stopped it; streams
  still list the namespace errors read before it in `errors()`.
- Messages: the re-reader describes a tag's errors in order, but several
  unbound attribute prefixes or a malformed QName before another error in
  one tag repeat the first one's message, and a RELAX NG diagnostic names an
  unbound element by its local part.

### Recovery (`RECOVER`)

libxml2's `XML_PARSE_RECOVER` does not change its parser: errors still mark
the document not well-formed, but SAX keeps building the tree, and
`xmlCtxtGetDocument` returns it. yaxml does the same with one decision per
error site, `Budget::recover`: strict parsing returns the error, recovery
records it and the site continues with libxml2's repair. An error no site
repairs ends parsing: the reader closes what is still open with `End` (and
`EntityEnd`) events at that error's offset (past the reference, for an error
in entity replacement text, so every node's range holds its children's), so the DOMs, built from those
events, and every stream (`Reader`, `PushParser`, `BufferedReader`,
`TextReader`) recover alike. `errors()` on each lists the recovered errors
(the first 100, as libxml2's `XML_MAX_ERRORS`); a well-formed document has
none and the same tree or events as without `RECOVER`. The DTD-free stream
rereads, repairs characters and keeps undeclared references as the slice
reader does, so stream, slice reader and DOM events are the same for any
chunking (fuzzed; [streaming.md](streaming.md#recovery-and-blanks)).

A recovered document can have no element, as libxml2's (only empty input
stays an error). `Document::document_element` and
`OwnedDocument::document_element` (`xmlDocGetRootElement`, DOM's
`documentElement`) return `None` then; `root_element` keeps its signature and
returns the synthetic root, as it already did for an HTML document without an
element. Callers that parse with `RECOVER` (and bindings, where `None` maps to
a null root) use `document_element`; every other caller keeps the guarantee
that a successful parse has an element.

| Error | Tree (libxml2 and yaxml) |
| --- | --- |
| Mismatched or malformed end tag | Ends the open element. With none open (after the root) parsing stops. |
| End of input inside content | Closes the open elements. A start tag cut off by the end is an empty element (UTF-8 documents without a DOCTYPE; elsewhere parsing stops before it). |
| Malformed attribute (`a=1`, `a="1"b`, no value), a character reference libxml2 reads as zero in a value (`&#0;`, `&#12a;`) | The element ends there, empty, with the attributes before it; the rest of the tag is reread as content (`<a b=1>x` gives `<a/>1&gt;x`). |
| `<` in an attribute value (declared or not; replacement text's `<` empties the value), duplicate attributes | Kept. |
| Namespace errors | As without `RECOVER` ([Namespace errors](#namespace-errors)). |
| A prefix declared again in one tag | Dropped. |
| Malformed reference | Dropped as far as libxml2 reads it (`&`, `&name`, `&#x4` of `&#x4G;`); a complete reference to a non-character is U+FFFD, `&#0;` nothing. |
| Undeclared or unparsed entity reference | An empty `EntityRef` node (without `NOENT`). |
| Unexpandable reference in an attribute value (with a DOCTYPE) | yaxml empties the value. |
| Character outside `Char` | Dropped from text, U+FFFD in an attribute value; a comment, PI or CDATA section ends at it (and is not kept), and parsing reads on from it. |
| Invalid UTF-8 | Each byte that starts no sequence reads as U+FFFD (`xmlCurrentCharRecover`), reported once. |
| `]]>` in text, `--` in a comment | Kept. |
| Misplaced or miscased XML declaration | A processing instruction. |
| Invalid PI target | The longest Name there is the target; without one `<?` is dropped and parsing reads on after it. |
| Invalid element name, `<!x`, a DOCTYPE inside the root | The longest Name there names the element; without one `<` is dropped and parsing reads on after it. |
| Invalid XML declaration pseudo-attribute, unsupported encoding | Ignored; the detected encoding is kept and the label dropped. |
| Missing space libxml2 only reports (after `<!DOCTYPE`, `SYSTEM`, `PUBLIC`, a public identifier, `<!ENTITY`, `%`, an entity or element name, around `NDATA`, `<!ATTLIST`, `#FIXED`) | Read on. |
| Other DTD error | The DOCTYPE keeps the header (`xmlParseDocTypeDecl`'s reading: no name is an empty one, a public identifier ends at a non-PubidChar) and the declarations before the error, an entity whose value was read and the ATTLIST definitions read included. The document resumes where libxml2's does: at the error in the subset, else after the header's `>` or where the header ends; anything there but markup ends parsing. |
| Content after the root element | Parsing stops; comments and PIs before it stay. |
| No element (text, markup or a DTD error before the root) | The document has no element. |

Fatal, as in strict parsing: resource limits (libxml2 stops there but keeps
the partial tree), entity loops, allocation failure and fatal resolver errors
(libxml2 reads on without the resource).
`tests/recover.rs` covers each row, and `yaxmllint --recover` is compared
with `xmllint --recover` (`tests/yaxmllint.rs`): libxml2's `test/errors`
agree on 37/45 inputs (82.22%; 23/45 before the repairs below), the XMLTS
not-wf documents on 1315/1498 (87.78%; 717/1498 before), give or take three
that flip between runs as libxml2 writes notations in hash order.
`streams_recover_against_xmllint` (`tests/recover.rs`) compares the push
parser's tree, as `xmllint --walker --debug` lists it, with libxml2's: its
pull tree (`--recover`) on 36/45 `test/errors` inputs (80.00%) and 1292/1498
XMLTS not-wf documents (86.25%), the same as the DOMs' events (80.00%,
86.18%), its push tree (`--recover --push`) on 33/45 (73.33%) and 1272/1498
(84.91%), with `--noblanks` on 34/45 (75.56%) and 1270/1498 (84.78%).
libxml2's push and pull trees differ on 4/45 and 20/1498 themselves (its push
parser drops a nameless tag that its pull parser reads as text); yaxml has
one recovery. The text reader agrees with `xmllint --recover --stream --debug`
on 10/45 (22.22%) and 543/1498 (36.25%) only, since libxml2's reader stops at
its first well-formedness error even with `RECOVER`. The known differences,
by design:

- With a DOCTYPE, content is read by the DTD stack, which recovers what the
  shared parser does (tags, names, namespaces, comments, end of input) but
  does not reread a malformed tag's rest, repair characters outside `Char`
  (it reads the prefix before the first), recover malformed or invalid
  character references in content, or keep an undeclared entity's empty
  reference without a DOCTYPE. Decoded input (UTF-16, byte charsets)
  without a DOCTYPE recovers as UTF-8 does. Entity loops stay fatal
  (libxml2 keeps the partial tree).
- The borrowed `Document` borrows its text and keeps the prefix before
  invalid UTF-8; `OwnedDocument` repairs it, and its offsets then count the
  repaired text. U+FFFD is a name character, so an invalid byte inside a
  name does not end it as libxml2's `XML_INVALID_CHAR` does. Streams end
  their input at invalid UTF-8, as `Document` does; after a DOCTYPE, at
  the token holding it or a character outside `Char` (the slice reader
  reads the prefix before the first in its whole input).
- A declaration libxml2 declares in part from a malformed external
  identifier (`PUBLIC "a&b"` keeps `PUBLIC "a"`), an entity value with a
  parameter-entity reference in the internal subset, and a malformed
  character reference in an entity value end the DOCTYPE; libxml2 declares
  them and reads on.
- Once a document is not well-formed, libxml2's `xmlParseReference`
  expands no entity reference in text, predefined ones included; yaxml keeps
  them, so that recovered output (where `save` writes `&gt;`) recovers to
  itself.
- Markup read as text after a tag error runs to that tag's `>` on the DTD
  stack (`1 < 2</doc>` keeps `</doc>` as text there).
- Unclosed comments and unterminated XML declarations follow the token rules
  (`<!--a--->` is a comment with an error; libxml2 reads to the end of input).

### Entity references without `NOENT`

libxml2's default keeps references: `xmlParseReference` calls the SAX
`reference` callback, and the tree gets an `XML_ENTITY_REF_NODE` whose content
is the entity's parsed nodes. yaxml keeps substituting internally, so limits
and errors are identical in both modes, and reports the boundaries:

- Streams emit `Event::EntityStart(name)`, the replacement's events, then
  `Event::EntityEnd`, rather than a lone reference event, so a consumer that
  ignores the two markers sees exactly the substituted stream. A reference
  libxml2 keeps without content (an external entity that is not loaded, or
  an undeclared one tolerated after an external subset or PE reference) is a
  start immediately followed by its end.
- `Document` and `OwnedDocument` build `EntityRef` nodes whose children are
  the replacement's nodes (`entity_name()`); text on either side is not
  merged across them. Each reference holds its own copy, expanded in its own
  namespace scope, where libxml2 shares one parse of the entity.
- `text_chunks` (`xmlNodeGetContent`) includes the replacement text.
- XPath, like libxml2's axes and node tests, never selects a reference or
  any node inside one; string values still include their text.
- `save` writes `&name;` and, under `FORMAT`, treats a reference as text
  when deciding indentation. The `Writer` writes the replacement content.
- C14N fails with `c14n::Error::EntityReference`, as libxml2 rejects an
  `XML_ENTITY_REF_NODE`.
- DTD validation, RELAX NG and XML Schema validate through references (the
  content model sees the replacement's children); libxml2's XML Schema
  validator instead reports an internal error.
- `TextReader` reports EntityReference nodes (type 5) and does not visit
  their content; `expand` writes the content into the expanded copy.
- XInclude does not look for inclusions inside references.
- Attribute values keep their references as libxml2's attribute children
  do (`xmlParseAttValueInternal`, then `xmlNodeParseAttValue`): a declared
  general reference stays `&name;`, character and predefined references are
  resolved (an `&` from one becomes `&#38;`), an undeclared entity tolerated
  after an external subset is dropped, and tokenized types normalize the
  whitespace around kept references but not inside them. Namespace
  declarations and `NOENT` always substitute. Both DOMs store this form
  (`unexpanded_attribute(position)`) only for an attribute that kept a
  reference; `attributes()` values stay substituted (`xmlGetProp`), and
  XPath, validation, C14N and patterns read them. `save` and `yaxmllint
  --xpath` write the kept form (`xmlSaveWriteAttrContent`); defaulted
  attributes (`DTDATTR`) keep their default's references. An owned
  `set_attribute_value` replaces the form with the new text. The `Writer`
  writes substituted values, as it writes reference content. Differences:
  libxml2's `xmlGetProp` concatenates a tokenized value's entity text
  unnormalized (`a &s; d` with `s` = ` b  c ` reads `a  b  c  d`; yaxml
  reads `a b c d`, the spec value and the `NOENT` value); libxml2 writes an
  `<!ATTLIST>` default's kept references escaped (`"p&amp;x;q"`), which is
  not a fixed point, so `save` writes the substituted default; XInclude
  copies, `TextReader` and the HTML parser substitute.

Match observable success behavior first: event/tree shape, namespace identity, normalized values, text coalescing, entity visibility and serialization bytes where specified. Error code/domain/severity and position matter next. Exact human error wording, allocation count, callback text-chunk boundaries and historical recovery quirks need separate documented contracts; streaming may split text into different chunks while preserving concatenated content. HTML parser options, reader properties, save flags and schema options keep their own mappings (`html::Options`, `ParserProperty`, `save::Options`, `xinclude::Options`).

## SAX2 callbacks

`yaxml::sax` (feature `sax`, in `full`) calls a `Handler` (libxml2's
`xmlSAXHandler` as `xmlSAXVersion(2)` fills it) from the slice `Reader`'s
events: `sax::parse(input, options, &mut handler)` is `xmlSAXUserParseMemory`
over any input `Transcoded` decodes. Each callback does nothing by default and
returns `ControlFlow`; `Break` is `xmlStopParser` (no further callbacks, not
even `end_document`, and `parse` returns `Ok`). `Reader::dtd` exposes the
declarations read so far to any pull caller. The order is libxml2's:
`start_document` (with the XML declaration), `internal_subset`, the internal
subset's declarations, `external_subset` (for every DOCTYPE), the external
subset's declarations, then the content; kept errors (warnings, namespace
errors, repaired `RECOVER` errors) come before the event they precede, the
error that ends the parse goes to `fatal_error`, then `end_document` (neither
document callback for empty input, as libxml2's "Document is empty").
`start_element` gets the attribute values libxml2's `startElementNs` does: DTD
defaults (`#FIXED` included, normalized) after the specified attributes with or
without `DTDATTR`, and without `NOENT` entity references kept as written and an
`&` from `&amp;` or `&#38;` as `&#38;`; namespace declaration values are
substituted. `tests/sax.rs` pins transcripts recorded from libxml2 2.15.4's
default SAX2 handlers wrapped to log each call.

Differences:

- Declarations are reported by kind (entities, notations, then each element
  type with its attribute lists) after each subset, not interleaved in source
  order. A repeated declaration, and comments and PIs inside the DTD, are not
  reported.
- Without `NOENT` a reference is `reference` alone. libxml2 also reports the
  content of the first reference to each entity before `reference`, as it
  parses the entity into its node list. With `NOENT` every reference's content
  is reported in full; libxml2 replays later references as their text only,
  without their elements.
- libxml2's queries to the handler (`getEntity`, `getParameterEntity`,
  `resolveEntity`, `isStandalone`, `hasInternalSubset`, `hasExternalSubset`)
  have no counterpart: the parser keeps the declarations and a `Resolver`
  loads resources. There is no `ignorableWhitespace`: libxml2's `areBlanks`
  needs the tree node only its SAX2 builder sets, so for a SAX handler
  `NOBLANKS` changes nothing and blanks arrive as `characters`, declared
  element content included (checked with a custom handler on 2.15.4);
  `sax::parse` accepts the flag the same way. There is no SAX1
  `startElement`/`endElement`.
- `Handler::locate` (`setDocumentLocator` with the locator's queries:
  `Locator::line`, `column`, `system_id`, `offset`, and `window` =
  `xmlCtxtGetInputWindow` on the document input) is called when the place
  changes. The place is libxml2's parsing point: after the event's markup, at
  a start tag's `>` or `/>`, past the blanks after the XML declaration for
  `start_document`, and after a fatal error the end of the input (libxml2
  reads on with SAX disabled) unless the error is outside the root element
  (`tests/sax.rs` pins libxml2's lines and columns). Declaration callbacks get
  the end of the DOCTYPE (the root's start tag for the external subset), and
  entity content the end of the reference; libxml2 reports the declaration's
  own place and places in the entity's text.

## Debugging dumps

`yaxml::debug` (feature `debug`, in `full`) ports debugXML.c's dumps over an
`OwnedDocument`: `dump_document` (`xmlDebugDumpDocument`, `xmllint --debug`),
`dump_document_head`, `dump_dtd`, `dump_entities`, `dump_node`,
`dump_one_node`, `dump_node_list`, `dump_attribute`, `dump_attributes`,
`dump_string`, `check_document` (`xmlDebugCheckDocument`) and, with
`xpath`, `dump_xpath_object` (`xmlXPathDebugDumpObject`). Each returns
the text libxml2 writes. `tests/debug.rs` pins xmllint output for XML and HTML
documents and every entry point; its ignored differential runs every XMLTS
document both parsers accept through `xmllint --debug` (`YAXML_XMLLINT`,
`YAXML_SUITES`): 1,991 of 1,999 agree, and the 8 that differ are listed there
with their reasons.

Differences:

- Text nodes never show libxml2's ` compact`/` interned` storage notes.
- An entity declaration's children come from a kept reference to it, in
  content or in an attribute value. Under `NOENT` there is none, so a
  declaration has no children, and an ATTLIST default always shows its
  references (libxml2 substitutes them under `NOENT`).
- Entity values and originals hold normalized line ends; libxml2 keeps the
  CR of a CRLF.
- A PI without data never shows `content=`; libxml2 prints an empty one for
  `<?pi ?>`.
- `dump_entities` lists entities in declaration order (libxml2: hash order).
- `check_document` reports detached roots (5013) and names outside the Name
  production (5034). libxml2's link, dictionary, parent and namespace-scope
  checks test invariants the owned tree keeps by construction.

## Constraints and deliberate boundaries

The safe core can use `std`, safe collections and memchr. This restriction does not automatically permit unsafe code in local adapters or new dependencies. SIMD inside the allowed memchr dependency follows that dependency's implementation policy; the prohibition should be enforced on yaxml source with `forbid(unsafe_code)`.

libxml2 optionally uses iconv/ICU, zlib and platform dynamic-loading functions. Under the dependency policy, built-in legacy encodings and compression require original safe implementations, generated checked-in tables with provenance, or explicit caller-provided conversion/decompression outside the core. A resolver cannot grant automatic network/file access just because input contains a URI. Native dynamic loading cannot be reproduced safely with only standard-library safe APIs. Preserve an explicit unsupported result until a permitted solution exists.

The [2.15.0 release announcement](https://discourse.gnome.org/t/libxml2-2-15-0-released/31397) records removal of the built-in HTTP client and LZMA, Schematron disabled by default, and planned removals. Keep removed/legacy stubs in the inventory without making their old implementation a requirement for the default profile. XSLT is supplied by libxslt, not libxml2; an XSLT engine is outside this catalogue. XML Schema 1.1 and a complete WHATWG HTML5 tree builder are not implied by libxml2 compatibility.

No implementation can promise superior performance on every workload or prove the absence of vulnerabilities with fuzzing coverage alone. Publish measurements per workload and an explicit coverage denominator. Every public input surface, option family, decoder, state transition, mutation and serializer needs a fuzz target or a documented exclusion. Unreached code is a burndown item, not permission to claim 100%.

## Acceptance and burndown

For each feature, track implementation, happy-path tests, malformed/adversarial tests, differential cases, fuzz target and measured coverage, then benchmarks. A feature is complete only when its observable contract is recorded and those checks pass. Unsupported features return structured errors; permissive parsing must never discard unsupported declarations silently.

Start with the bounded UTF-8 XML scanner and pull events, then construct the read-only DOM from the same semantic parser. Add namespaces and normalization before advertising an ordinary XML parser. Make streaming chunk invariance, error determinism, limits, and panic freedom release gates from the first slice. Add encodings, mutation and output next; layer DTDs, XPath, validators and inclusion over the resulting shared data model. Keep the low-level scanner internal so malformed syntax cannot bypass semantic checks through another public facade.

## API inventory method and limits

The inventory contains 1,405 functions, 22 variables, 86 callback typedefs, 202 other typedefs, 48 enums, 1,288 enum values, 284 macros, 55 named structs, and 666 member paths. It includes deprecated compatibility declarations and declarations hidden behind build options. The `status` column is `unmapped` for 4,056 rows (the four `empty_header` rows are `catalogued`; counted with `awk` on 2026-10-19), so the column carries no per-symbol progress and the tables above are the only status record: listing a C identifier does not claim that a corresponding Rust operation or C symbol is implemented. Priority ranges identify modules spanning several roadmap stages; the feature table determines operation-level order.

`deprecated_marker=yes` records an adjacent `XML_DEPRECATED` attribute or a member's `XML_DEPRECATED_MEMBER`. Nested member paths inherit the marker of an enclosing member, such as `_xmlCharEncodingHandler.input`. `not_marked` does **not** mean supported, recommended or non-deprecated: upstream also describes deprecations in documentation comments. This column is a mechanical hint, not a full lifecycle classification. For example, the parser context's public members include documented deprecations without compiler attributes.

The initial lexical sweep strips C comments, collects `XMLPUBFUN`/`XMLPUBVAR` declarations, callback and simple typedefs, enums and enumerators, named structs and member declarations, and non-underscore `#define` identifiers. It removes preprocessor directives before reading member names and excludes the export macro's `__declspec` expansion. Nested encoding-handler unions use qualified paths such as `_xmlCharEncodingHandler.input.func`; function-pointer members are fields, while named callback typedefs are callbacks. Include guards beginning with underscores are excluded. Internal compatibility macros exposed by public headers remain listed.

A [configured Clang AST and static-symbol audit](archive/validation/libxml2-api-audit-21504.md) corrected five omissions: one single-line function declaration in `xmlexports.h` and four array variables. The catalogue retains both sides of conditional APIs. The audited build exposes 1,367 functions and 22 variables; all 1,389 names are defined with public visibility. Its 119 additional private-external symbols are not public API additions. A controlled header-feature view covers disabled declarations without claiming those implementations are present in the built library.

The TSV does not encode configured availability, full signatures, evaluated constants or ABI layouts. `xmlversion.h.in` is the version/configuration template; each build's configured `xmlversion.h` needs separate verification. This audit covers one arm64 macOS static build and controlled header feature flags, not every platform, option combination or shared-library export surface. Historical releases and removed APIs absent from these headers need separate compatibility inventories if targeted. Complete C source or binary compatibility remains unimplemented; the pinned headers are authoritative for signatures.
